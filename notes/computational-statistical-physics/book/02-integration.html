2  Numerical and Monte Carlo Integration

Integrals are everywhere in physics (partition functions, expectation values, the action, the overlap of two wave functions), and only a tiny fraction of them can be done with pen and paper, so the first real numerical task of the course is to compute \(\int_a^b f(x)\,dx\) for an \(f\) we can evaluate but can’t integrate. We’ll do it two completely different ways. The first half of the chapter puts points on a grid and approximates \(f\) by polynomials between them, which is extremely accurate in one dimension and hopeless in fifty. The second half throws random points at the integral instead, which is crude in one dimension and the only thing that works in fifty, and it’s also our first contact with Monte Carlo, error bars and the central limit theorem, which we’ll need for every simulation from here on.

2.1 Integrating On A Grid

We want \[ I = \int_a^b f(x)\,dx \] for a function \(f\) we can evaluate anywhere in \([a, b]\) (no singularities, for now). The idea behind all the elementary methods is the same. We chop \([a, b]\) into \(N\) intervals of equal width \(h = (b-a)/N\), giving \(N+1\) points \(x_i = a + ih\) with values \(f_i = f(x_i)\), then we approximate \(f\) on a few neighboring intervals by the polynomial that passes through those points, and we integrate the polynomial exactly. A straight line through two points gives the trapezoidal rule, and a parabola through three gives Simpson’s rule.

Code 
f = lambda x: 1 + 0.6 * np.sin(2.2 * x) + 0.3 * x
xs = np.linspace(0, 4, 400); xi = np.linspace(0, 4, 5)

2.1.1 The trapezoidal rule

On a single interval \([x_0, x_1]\) the straight line through the endpoints is \(f(x_0 + \delta) \approx f_0 + \delta(f_1 - f_0)/h\), and integrating it over \(0 \le \delta \le h\) gives \[ \int_{x_0}^{x_1} f(x)\,dx \approx \frac{h}{2}\,(f_0 + f_1), \] which is just the area of a trapezoid (so we could’ve written it down directly, but going the long way works for any polynomial order). The interesting question is how big the error is. Taylor expand \(f\) around \(x_0\) and integrate term by term, \[ \int_0^h f(x_0+\delta)\,d\delta = h f_0 + \frac{h^2}{2} f_0' + \frac{h^3}{6} f_0'' + O(h^4), \] and do the same for the rule, using \(f_1 = f_0 + h f_0' + \tfrac{h^2}{2} f_0'' + \cdots\), \[ \frac{h}{2}(f_0 + f_1) = h f_0 + \frac{h^2}{2} f_0' + \frac{h^3}{4} f_0'' + O(h^4). \] The first two terms agree and the third doesn’t, so a single interval is off by \(-\tfrac{h^3}{12}f''\). That’s the step error, \(O(h^3)\). Adding up all \(N\) intervals, \[ T(h) = h\left(\tfrac{1}{2}f_0 + f_1 + f_2 + \cdots + f_{N-1} + \tfrac{1}{2}f_N\right), \] we pay \(N = (b-a)/h\) step errors, so the global error is \(N \times O(h^3) = O(h^2)\), and more precisely \(T(h) - I \approx \tfrac{h^2}{12}\big[f'(b) - f'(a)\big]\) (the sum of \(h f''\) over the intervals is an integral of \(f''\)). Halving \(h\) cuts the error by four.

2.1.2 Simpson’s rule

Now take three points and fit a parabola \(f(x_0 + \delta) \approx c_0 + c_1\delta + c_2\delta^2\). The three conditions at \(\delta = 0, h, 2h\) give a little linear system with the solution \(c_0 = f_0\), \(c_1 = -(3f_0 - 4f_1 + f_2)/(2h)\), \(c_2 = (f_0 - 2f_1 + f_2)/(2h^2)\), and integrating the parabola over \([0, 2h]\) and collecting terms gives Simpson’s rule \[ \int_{x_0}^{x_2} f(x)\,dx \approx \frac{h}{3}\,(f_0 + 4f_1 + f_2). \] A parabola is exact for polynomials of degree two, so we’d naively expect the first error to come from the cubic term and be \(O(h^4)\) per step. But something nicer happens, and the cleanest way to see it is to expand around the middle point instead, \(f(x_1 + t) = f_1 + tf' + \tfrac{t^2}{2}f'' + \tfrac{t^3}{6}f''' + \tfrac{t^4}{24}f'''' + \cdots\), and integrate over the symmetric window \(-h \le t \le h\). Every odd power of \(t\) integrates to zero, including the cubic one, \[ \int_{-h}^{h} f(x_1+t)\,dt = 2h f_1 + \frac{h^3}{3} f'' + \frac{h^5}{60} f'''' + \cdots, \] and since the rule is also symmetric, it gets the cubic term right for free. Expanding the rule the same way (\(f_0 + f_2 = 2f_1 + h^2 f'' + \tfrac{h^4}{12}f'''' + \cdots\)) gives \(\tfrac{h}{3}(f_0 + 4f_1 + f_2) = 2hf_1 + \tfrac{h^3}{3}f'' + \tfrac{h^5}{36}f'''' + \cdots\), so the step error is \(-\tfrac{h^5}{90}f''''\) and the global error is \(O(h^4)\). Symmetry buys us a whole order. (We’ll see the exact same trick again when we derive the Verlet algorithm in Section 3.2, and again in Numerov’s method in Section 4.1.2.)

2.1.3 Implementations and a convergence check

Both rules are a few lines of NumPy, and the thing I want to stress is that we should test them, by checking that the error falls at the rate we just derived. We’ll use \(\int_0^1 e^x\,dx = e - 1\).

def trapezoid(f, a, b, N):
    x = np.linspace(a, b, N + 1)            # x_i computed from i, never accumulated
    y = f(x)
    return (b - a) / N * (0.5 * y[0] + y[1:-1].sum() + 0.5 * y[-1])

def simpson(f, a, b, N):
    if N % 2:
        raise ValueError("Simpson's rule needs an even N")
    x = np.linspace(a, b, N + 1)
    y = f(x)
    return (b - a) / N / 3 * (y[0] + 4 * y[1:-1:2].sum() + 2 * y[2:-1:2].sum() + y[-1])

exact = math.e - 1
print("    N    trapezoid error   ratio     Simpson error   ratio")
prev = None
for N in [4, 8, 16, 32, 64, 128]:
    et, es = trapezoid(np.exp, 0, 1, N) - exact, simpson(np.exp, 0, 1, N) - exact
    r = f"{prev[0] / et:6.2f}        {prev[1] / es:7.2f}" if prev else ""
    print(f"{N:5d}   {et:14.3e}   {es:14.3e}   {r}")
    prev = (et, es)

The trapezoid error falls by 4 per halving and Simpson by 16, exactly as promised. (Notice also that the trapezoid error is positive, matching \(\tfrac{h^2}{12}[f'(1) - f'(0)] > 0\). Checking even the sign of an error against your derivation is a cheap and surprisingly effective way to catch bugs.) If you push \(N\) far enough, Simpson’s error will eventually stop falling and start bouncing around \(10^{-16}\), which is roundoff from Section 1.2 taking over.

2.1.4 Open formulas and the midpoint rule

The rules above use the endpoints \(a\) and \(b\), so if the integrand blows up at an endpoint (say \(1/\sqrt{x}\) at \(x = 0\)) we can’t even evaluate them. Open formulas avoid the endpoints, and the simplest is the midpoint rule, which samples each interval at its center, \[ I \approx M(h) = h\big(f_{1/2} + f_{3/2} + \cdots + f_{N-1/2}\big). \] Expanding around the center of an interval, the odd terms cancel again, and the step error is \(+\tfrac{h^3}{24}f''\), half the trapezoid’s error and with the opposite sign. So the midpoint rule is also globally \(O(h^2)\) (and, as a cute aside, \(\tfrac{2}{3}M + \tfrac{1}{3}T\) cancels the leading error and is exactly Simpson’s rule on the doubled grid). A warning comes with open formulas, though. The error estimates assume \(f\) is smooth, and a function with an endpoint singularity isn’t, so open formulas let us evaluate the integral, but the convergence can be painfully slow, which we’ll quantify in Section 2.2.4.

Here’s a tangent that surprises almost everyone. For a smooth periodic function integrated over a full period, the trapezoidal rule is spectacularly accurate. The error formula \(\tfrac{h^2}{12}[f'(b) - f'(a)]\) has the endpoint derivatives cancel, and so do all the higher corrections in the Euler-Maclaurin formula (next section), so the error falls faster than any power of \(h\).

g = lambda x: np.exp(np.cos(x))                 # periodic with period 2 pi
exact_g = 2 * np.pi * special.i0(1.0)           # the exact answer is a Bessel function
for N in [2, 4, 8, 16]:
    print(f"N = {N:2d}   trapezoid error {trapezoid(g, 0, 2 * np.pi, N) - exact_g: .3e}")

N =  4   trapezoid error  3.440e-02
N =  8   trapezoid error  1.252e-06
N = 16   trapezoid error  0.000e+00

With 16 points we’re at roundoff. This is secretly why the fast Fourier transform is so accurate, and we’ll use it in Section 4.4.4.

2.2 Doing Better Than Simpson

We could keep going and derive rules from cubic, quartic and higher polynomials, but it’s a bad idea. High-order equally spaced rules develop large weights of alternating sign, which amplify roundoff, and there are two much better routes to high accuracy: one extrapolates the trapezoidal rule, and the other gives up on equally spaced points altogether.

2.2.1 Romberg integration

The trapezoidal error has a remarkable structure. The Euler-Maclaurin formula says that, for a smooth \(f\), it contains only even powers of \(h\), \[ T(h) - I = \sum_{k=1}^{\infty} \frac{B_{2k}\,h^{2k}}{(2k)!}\Big[f^{(2k-1)}(b) - f^{(2k-1)}(a)\Big] = \epsilon_1 h^2 + \epsilon_2 h^4 + \epsilon_3 h^6 + \cdots, \] where the \(B_{2k}\) are Bernoulli numbers, with \(B_2 = 1/6\) reproducing the \(h^2/12\) we found by hand. (Strictly speaking this series is asymptotic rather than convergent, but the first several terms are what matter for us.) The point is that \(T(h)\) is a polynomial in \(h^2\) with unknown coefficients but a known form, and that lets us extrapolate to \(h = 0\).

Here’s how. Let \(T_k\) be the trapezoid result with \(2^k\) intervals. Combine two of them to kill the \(h^2\) term, \[ \frac{4T(h/2) - T(h)}{3} = I + O(h^4), \] (which, if you write it out, is exactly Simpson’s rule). Then combine two of those with weights \(16\) and \(-1\) to kill the \(h^4\) term, and so on. In general, with \(R_{k,0} = T_k\), \[ R_{k,j} = R_{k,j-1} + \frac{R_{k,j-1} - R_{k-1,j-1}}{4^j - 1}, \] and \(R_{k,j}\) has error \(O(h^{2j+2})\). This is called Richardson extrapolation, and it’s a really general idea: whenever you know the form of an error expansion, you can cancel it term by term. One more trick makes Romberg cheap. Going from \(T_k\) to \(T_{k+1}\) keeps every old point and only adds the midpoints, so \(T_{k+1} = \tfrac{1}{2}T_k + h_{k+1}\sum(\text{new points})\) and no function evaluation is ever wasted.

2.2.2 Gaussian quadrature

Every rule so far has the form \(I \approx \sum_i w_i f(x_i)\), with the points \(x_i\) fixed in advance on an even grid and only the weights chosen cleverly. Gaussian quadrature asks what happens if we choose the points too. An \(n\)-point rule then has \(2n\) free parameters, and a polynomial of degree \(2n-1\) also has \(2n\) coefficients, so we can hope to integrate all such polynomials exactly, and that hope comes true. (The trapezoid and Simpson rules, with \(n+1\) points, are exact for degree \(n\) or so. Gauss does about twice as well with the same number of points.)

The construction on \([-1, 1]\) uses the Legendre polynomials \(P_n\), which are orthogonal: \(\int_{-1}^1 P_n\, q\,dx = 0\) for every polynomial \(q\) of degree less than \(n\). Choose the nodes \(x_i\) to be the \(n\) roots of \(P_n\), and the weights so that the rule integrates every polynomial of degree up to \(n-1\) exactly (always possible with \(n\) points). Now take any polynomial \(p\) of degree up to \(2n-1\) and divide it by \(P_n\), giving \(p = q P_n + r\) with \(q\) and \(r\) both of degree at most \(n-1\). Then \[ \int_{-1}^{1} p\,dx = \underbrace{\int_{-1}^1 q P_n\,dx}_{0 \text{ by orthogonality}} + \int_{-1}^1 r\,dx = \sum_i w_i r(x_i) = \sum_i w_i p(x_i), \] where the last step used \(P_n(x_i) = 0\) at every node. That’s the whole proof, and I think it’s one of the prettiest arguments in numerical analysis. NumPy hands us the nodes and weights.

x5, w5 = np.polynomial.legendre.leggauss(5)
print("nodes  ", np.round(x5, 6))
print("weights", np.round(w5, 6))

def gauss(f, a, b, n):
    x, w = np.polynomial.legendre.leggauss(n)
    return 0.5 * (b - a) * np.sum(w * f(0.5 * (b - a) * x + 0.5 * (a + b)))   # map [-1,1] to [a,b]

for n in [2, 3, 4, 5, 6]:
    print(f"n = {n}: error {gauss(np.exp, 0, 1, n) - (math.e - 1): .2e}")

Five function evaluations give ten correct digits, where Simpson needed more than a hundred. The catch is that Gauss is great for smooth integrands and much less so for anything with kinks, and that the nodes change completely when you change \(n\), which makes error estimation awkward. That brings us to adaptive methods.

2.2.3 Adaptive integration

A fixed grid spends as many points on the flat parts of an integrand as on the busy parts. Adaptive methods estimate the error on each subinterval and refine only where it’s large. The trick for Gaussian rules is the Kronrod extension, which adds \(n+1\) cleverly chosen nodes to an \(n\)-point Gauss rule to get a \((2n+1)\)-point rule of much higher degree that reuses every Gauss evaluation, so the difference between the two results is an error estimate that costs nothing extra (the same spirit as reusing points in Romberg). The workhorse library behind scipy.integrate.quad (QUADPACK) pairs a 10-point Gauss rule with its 21-point Kronrod extension and keeps bisecting whichever subinterval has the largest estimated error until the total meets the tolerance.

calls = [0]
def peaked(x):
    calls[0] += 1
    return 1 / ((x - 0.3) ** 2 + 1e-4)            # a narrow Lorentzian at x = 0.3

val, err = integrate.quad(peaked, 0, 1, epsabs=1e-12, epsrel=1e-12, limit=200)
exact_p = 100 * (math.atan(70) + math.atan(30))
print(f"quad: {val:.14f}  estimated error {err:.1e}  true error {val - exact_p:.1e}  ({calls[0]} evaluations)")
print(f"Simpson with 1000 intervals: error {simpson(peaked, 0, 1, 1000) - exact_p:.1e}")

2.2.4 Singular integrands and infinite ranges

Some integrals refuse to be smooth. An integrable singularity like \(1/\sqrt{x}\) at \(x = 0\) has a finite integral, but no polynomial can approximate the function near the singular point, so all of our error estimates break down. We can see how badly with the midpoint rule on \(\int_0^1 x^{-1/2}\,dx = 2\).

def midpoint(f, a, b, N):
    h = (b - a) / N
    return h * f(a + h * (np.arange(N) + 0.5)).sum()

for N in [10, 100, 1000, 10000]:
    print(f"N = {N:5d}   midpoint error {midpoint(lambda x: x**-0.5, 0, 1, N) - 2: .4f}")
N =    10   midpoint error -0.1911
N =   100   midpoint error -0.0605
N =  1000   midpoint error -0.0191
N = 10000   midpoint error -0.0060

Ten times more points buy only a factor of \(\sqrt{10} \approx 3.16\), so the error goes like \(h^{1/2}\), and nearly all of it comes from the very first cell. There the exact integral is \(\int_0^h x^{-1/2}\,dx = 2\sqrt{h}\), while the rule gives \(h \times (h/2)^{-1/2} = \sqrt{2}\sqrt{h}\), an error of \((\sqrt{2} - 2)\sqrt{h} \approx -0.59\sqrt{h}\) all by itself. Getting six digits this way would take something like \(10^{12}\) points.

The fix is to deal with the singularity analytically before the computer ever sees it. The two standard tricks are a change of variables and subtracting the singular part. For \(\int_0^1 g(x)/\sqrt{x}\,dx\) with smooth \(g\), the substitution \(x = t^2\), \(dx = 2t\,dt\) gives \(\int_0^1 2g(t^2)\,dt\), which is perfectly smooth. Infinite ranges are handled the same way: \(x = t/(1-t)\) maps \([0, 1)\) onto \([0, \infty)\), or for something like \(\int_0^\infty e^{-x}g(x)\,dx\) we can just cut the range off where the integrand is below our tolerance, or (better) use Gauss-Laguerre quadrature, which is built for exactly that weight.

2.2.5 More than one dimension, the hard way

A multidimensional integral can be done one dimension at a time with the rules above. In two dimensions, possibly with \(y\)-dependent limits, \[ I = \int_{a_y}^{b_y} dy\, F(y), \qquad F(y) = \int_{a_x(y)}^{b_x(y)} f(x, y)\,dx, \] and from the outer integral’s point of view \(F(y)\) is just an expensive function. Here’s \(\int r^2\) over the unit disk, whose exact value is \(\pi/2\).

F = lambda y: integrate.quad(lambda x: x**2 + y**2, -math.sqrt(1 - y**2), math.sqrt(1 - y**2))[0]
I2, err2 = integrate.quad(F, -1, 1)
print(I2, math.pi / 2)
1.5707963267947727 1.5707963267948966

The trouble is cost. If a one-dimensional integral needs \(M\) function evaluations, nesting \(D\) of them needs \(M^D\). With a modest \(M = 20\), a three-dimensional integral costs 8000 evaluations, a six-dimensional one \(6.4 \times 10^7\), and a ten-dimensional one \(10^{13}\). And a statistical mechanics problem with \(N\) particles in three dimensions is a \(3N\)-dimensional integral, so for a hundred particles this isn’t slow, it’s impossible. This is the curse of dimensionality, and it’s what Monte Carlo is for.

2.3 Monte Carlo Integration

“Monte Carlo” in physics means any method that uses random numbers (after the casino), and Monte Carlo integration is the simplest of them. The statistical ideas it forces on us, error bars, binning, the central limit theorem, are the same ones we’ll need for every simulation later, so it’s worth going slowly here.

2.3.1 An integral is an average

The starting observation is almost a tautology. The mean value of \(f\) over a region of volume \(V\) is, by definition, the integral divided by the volume, \(I = \int_V f(\mathbf{x})\,d\mathbf{x} = V\langle f\rangle\). So instead of evaluating \(f\) on a grid, we can draw \(N\) points \(\mathbf{x}_1, \ldots, \mathbf{x}_N\) independently and uniformly from the region and use the sample mean, \[ I \approx V\bar{f}, \qquad \bar{f} = \frac{1}{N}\sum_{i=1}^{N} f(\mathbf{x}_i). \] Two facts about this estimate drive everything else. First, it’s unbiased: each \(f(\mathbf{x}_i)\) is a random variable whose average over all possible draws is exactly \(\langle f\rangle\), so the average of \(\bar{f}\) is \(\langle f\rangle\) too, for any \(N\). Second, its variance shrinks like \(1/N\). Write \(\sigma_f^2 = \langle f^2\rangle - \langle f\rangle^2\) for the variance of the integrand over the region. Variances of independent random variables add, and dividing by \(N\) divides the variance by \(N^2\), so \[ \operatorname{Var}(\bar{f}) = \frac{\sigma_f^2}{N}, \qquad \text{error} \approx V\frac{\sigma_f}{\sqrt{N}} . \] The error falls like \(N^{-1/2}\) regardless of the dimension. That’s terrible in one dimension (the trapezoid does \(N^{-2}\)) and wonderful in a hundred.

2.3.2 The standard example, estimating π

Put the unit circle inside the square \([-1, 1]^2\) and integrate the indicator function that’s 1 inside the circle and 0 outside. The square has area 4 and the circle has area \(\pi\), so the fraction of hits should approach \(\pi/4\).

rng = np.random.default_rng(1)
def estimate_pi(N, rng):
    x = rng.uniform(-1, 1, N)
    y = rng.uniform(-1, 1, N)
    return 4 * np.mean(x**2 + y**2 <= 1)          # area of square times hit fraction

2.3.3 Error bars, and what they mean

A Monte Carlo result without an error bar isn’t a result. The convention is to quote \(A \pm \bar{\sigma}\), where \(\bar{\sigma}\) is one standard deviation of the probability distribution of the computed mean. If that distribution is Gaussian, the true value lies within \(\pm\bar{\sigma}\) about 68% of the time, within \(\pm 2\bar{\sigma}\) about 95% of the time, and within \(\pm 3\bar{\sigma}\) about 99.7% of the time.

In practice we estimate \(\bar{\sigma}\) from the data. Suppose we have \(M\) independent estimates \(A_1, \ldots, A_M\), each computed the same way. Their mean \(\bar{A}\) is our best estimate, and the spread of the individual values estimates the width of their distribution, \[ \sigma_A^2 \approx \frac{1}{M}\sum_{i=1}^{M}\big(A_i - \bar{A}\big)^2 . \] But \(\sigma_A\) is not the error of \(\bar{A}\), which is a point people get wrong constantly. As \(M\) grows, \(\sigma_A\) approaches a constant (the intrinsic width of the distribution), while \(\bar{A}\) keeps getting better. The error of the mean is smaller by \(\sqrt{M}\), for the same reason as in Section 2.3.1, and correcting for the fact that we estimated the mean from the same data gives the unbiased version \[ \bar{\sigma} = \sqrt{\frac{1}{M(M-1)}\sum_{i=1}^{M}\big(A_i - \bar{A}\big)^2} . \]

2.3.4 Binning and the central limit theorem

The 68% interpretation assumes Gaussian fluctuations, and individual samples are almost never Gaussian (in the π example each one is 0 or 1). The cure is binning. We group the samples into \(M\) bins of \(N\) samples each, compute the average within each bin, and treat the \(M\) bin averages as our data. The central limit theorem guarantees that, whatever the distribution of single samples, the average of \(N\) of them becomes Gaussian as \(N\) grows, provided the single-sample variance is finite. (Hold on to that last condition, Section 2.4.1 is about what happens when it fails.)

The π problem lets us watch the Gaussian emerge exactly. With \(N\) samples per bin, the bin average can only take the values \(m/N\), and the number of hits \(m\) is binomial, \[ P\Big(A = \frac{m}{N}\Big) = \binom{N}{m} p^m (1-p)^{N-m}, \qquad p = \frac{\pi}{4}. \] For \(N = 1\) this is two spikes at 0 and 1, and as \(N\) grows the spikes crowd together into a bell curve.

p = math.pi / 4

2.3.5 Why Monte Carlo wins in high dimensions

We can make the comparison with grid methods sharp with a one-line argument. Spend \(N\) function evaluations on a \(D\)-dimensional grid. Each axis then gets \(N^{1/D}\) points, so the spacing is \(h \propto N^{-1/D}\), and a rule with global error \(O(h^p)\) (\(p = 2\) for the trapezoid, \(p = 4\) for Simpson) has error \[ \varepsilon_{\text{grid}} \propto h^p \propto N^{-p/D}, \qquad \varepsilon_{\text{MC}} \propto N^{-1/2}. \] Monte Carlo converges faster as soon as \(p/D < 1/2\), that is \(D > 2p\). Against the trapezoid rule Monte Carlo wins beyond four dimensions, and against Simpson beyond eight. Fancier grid rules push the crossover further for very smooth integrands, but for every grid method the exponent \(p/D\) eventually decays to zero, while \(N^{-1/2}\) doesn’t care about \(D\) at all. That’s why every high-dimensional integral in statistical mechanics, from the partition function of a gas to the path integral of a quantum system, gets done with random numbers.

2.3.6 A worked example, the volume of a D-dimensional ball

A nice test with a known answer is the volume of the unit ball in \(D\) dimensions, \[ V_D = \frac{\pi^{D/2}}{\Gamma(D/2 + 1)} . \] We sample the cube \([-1, 1]^D\), which has volume \(2^D\), and count points with \(|\mathbf{x}| \le 1\) (by symmetry it’s enough to sample one corner \([0, 1)^D\)).

def ball_volume(D, N, rng):
    x = rng.random((N, D))
    p = np.mean(np.sum(x**2, axis=1) <= 1)
    return 2**D * p, 2**D * math.sqrt(p * (1 - p) / N)

rng = np.random.default_rng(42)

It works beautifully up to about \(D = 10\), and then something goes wrong, and it’s worth understanding what. The relative error is \(\sqrt{(1-p)/(pN)}\), which blows up as the hit fraction \(p = V_D/2^D\) goes to zero, and \(p\) goes to zero really fast: the ball fills 79% of the square, 52% of the cube, and \(3.6 \times 10^{-6}\) of the 16-dimensional cube. Almost all the volume of a high-dimensional cube is in its corners. So with \(2 \times 10^5\) samples in \(D = 16\) we get maybe zero or one hit, and the estimate is junk. The integrand has become a needle in a haystack, and sampling the haystack uniformly is a waste. The fix is to sample where the integrand is, which is importance sampling (Section 2.4.4).

2.4 When Sampling Gets Hard

Everything in the last section rested on two assumptions: that the integrand has a finite variance, so the central limit theorem applies, and that we have a supply of numbers that behave like independent uniform random variables. Let’s poke at both.

2.4.1 A singular integrand and heavy tails

Modify the circle example by putting an integrable singularity at the center, \[ f(x, y) = \begin{cases} r^{-\alpha}, & r = \sqrt{x^2+y^2} \le 1, \\ 0, & r > 1. \end{cases} \] In polar coordinates the area element is \(r\,dr\,d\theta\), so the integral is \(2\pi\int_0^1 r^{1-\alpha}\,dr = 2\pi/(2-\alpha)\), finite for \(\alpha < 2\). Uniform Monte Carlo over the square will happily produce an estimate. The question is whether we can trust its error bar.

To find out, let’s work out the distribution of the sampled values. A uniform point inside the unit circle has radius \(r\) with density \(P(r) = 2r\) (the fraction of area between \(r\) and \(r + dr\) is \(2\pi r\,dr/\pi\)). Changing variables to \(f = r^{-\alpha}\), so \(r = f^{-1/\alpha}\), the densities are related by \(P(f) = P(r)\,|dr/df|\), which gives \[ P(f) = 2f^{-1/\alpha}\cdot\frac{1}{\alpha}f^{-1-1/\alpha} = \frac{2}{\alpha}\,f^{-1-2/\alpha}, \qquad f \ge 1 . \] A power-law tail! The mean \(\int f\,P(f)\,df\) converges when \(f^{-2/\alpha}\) decays faster than \(1/f\), which is \(\alpha < 2\) (consistent with the integral above). But the variance needs \(\int f^2 P(f)\,df < \infty\), which needs \(1 - 2/\alpha < -1\), that is \(\alpha < 1\). So for \(1 \le \alpha < 2\) we’re in a strange regime: the integral exists, the Monte Carlo estimate converges to it, but the variance of a single sample is infinite, the central limit theorem doesn’t apply, and the error bars our formula prints are meaningless (they’re dominated by the largest sample we happened to draw, and they converge more slowly than \(N^{-1/2}\)).

def singular_mc(alpha, N, M, rng):
    x, y = rng.uniform(-1, 1, (2, N))
    r2 = x**2 + y**2
    f = np.where(r2 <= 1, r2 ** (-alpha / 2), 0.0)
    bins = 4 * f.reshape(M, -1).mean(axis=1)
    return bins.mean(), bins.std(ddof=1) / math.sqrt(M)

rng = np.random.default_rng(7)
for alpha in [0.5, 1.5]:

For \(\alpha = 0.5\) everything behaves (errors of order one error bar, shrinking like \(N^{-1/2}\)). For \(\alpha = 1.5\) the error bars are erratic and the estimate tends to sit below the true value, because the rare huge samples near the center that the mean depends on usually haven’t been drawn yet, and the error bar can’t know about samples we haven’t drawn. The lesson I’d take away is to always look at the distribution of your samples (or at least how the error bar shrinks with \(N\)), not just the final number with its \(\pm\).

2.4.2 What a divergent integral looks like

At \(\alpha = 2\) the integral diverges logarithmically. Monte Carlo will still print a number for any finite \(N\), so it’s worth knowing what a divergence looks like in the output. We can even predict it. With \(N\) points in the square, the closest one to the origin typically lies at the radius \(r_0\) where the expected number of points inside is about one, \(N\pi r_0^2/4 \approx 1\). That point acts as an effective cutoff, so the estimate behaves like \[ A(N) \approx 2\pi\ln\frac{1}{r_0} \approx \pi\ln\frac{\pi N}{4} . \]

rng = np.random.default_rng(3)
Nmax = 2 * 10**6
n = np.arange(1, Nmax + 1)
fig, ax = plt.subplots(figsize=(6, 3.2))
for run in range(4):
    x, y = rng.uniform(-1, 1, (2, Nmax))
    r2 = x**2 + y**2
    f = np.where(r2 <= 1, 1 / r2, 0.0)
    ax.plot(n[99::100], (4 * np.cumsum(f) / n)[99::100], lw=0.8)
ax.plot(n[99:], np.pi * np.log(np.pi * n[99:] / 4), "k--", lw=1)
ax.set_xscale("log"); ax.set_xlabel("$N$"); ax.set_ylabel("running estimate"); ax.set_ylim(0, 60)
fig.tight_layout(); plt.show()

The curves from independent runs nearly overlap between the spikes, because the typical value of \(A(N)\) is well defined at every \(N\) even though its mean is infinite. The warning sign is an estimate that keeps drifting as \(N\) grows and never settles, which is really easy to miss if you only ever run one \(N\).

2.4.3 Pseudo-random numbers

Computers are deterministic, so the “random” numbers we use are pseudo-random: they come from a fixed rule, and the good ones just pass every statistical test anyone has thought of. In Section 1.4.2 we built the classic linear congruential generator \(x_n = (ax_{n-1} + c) \bmod m\). To build some intuition for how these things fail, let’s look at a tiny one, with \(m = 16\) and \(c = 1\), and try every multiplier.

def lcg_sequence(a, c, m, x0=0, n=None):
    xs, x = [], x0
    for _ in range(n or m):
        x = (a * x + c) % m
        xs.append(x)
    return xs

m = 16

Only \(a = 1, 5, 9, 13\) visit every residue (exactly the Hull-Dobell condition \(a \equiv 1 \pmod 4\)), and some of those are obviously not random at all (\(a = 1\) just counts). With realistic sizes the failures are subtler, and the most famous one is a generator called RANDU, \(x_{n+1} = 65539\,x_n \bmod 2^{31}\), which IBM shipped in the 1960s and which a lot of published physics used. Since \(65539 = 2^{16} + 3\), a two-line calculation shows \(x_{n+2} = 6x_{n+1} - 9x_n \pmod{2^{31}}\), so consecutive triples are linearly related and every triple of RANDU numbers lies on one of just 15 planes in the unit cube. You can see it if you look at the cube from the right angle.

def randu(n, seed=1):
    out = np.empty(n); x = seed
    for i in range(n):
        x = (65539 * x) % 2**31
        out[i] = x / 2**31
    return out

The lesson is to use a modern generator (NumPy’s default_rng is a good one), to seed it explicitly so your runs are reproducible, and to give each independent run (or each parallel process) its own seed, ideally through np.random.SeedSequence, which is designed so that streams from different seeds don’t overlap.

2.4.4 Importance sampling, a first look

The basic fix for both the heavy-tail problem and the empty-ball problem follows directly from the rest of this chapter. Instead of sampling uniformly, draw points from a probability density \(p(\mathbf{x})\) of our choosing, and rewrite the integral as an average under \(p\), \[ I = \int f(\mathbf{x})\,d\mathbf{x} = \int \frac{f(\mathbf{x})}{p(\mathbf{x})}\,p(\mathbf{x})\,d\mathbf{x} \approx \frac{1}{N}\sum_{i=1}^{N}\frac{f(\mathbf{x}_i)}{p(\mathbf{x}_i)}, \qquad \mathbf{x}_i \sim p . \] This estimate is unbiased for any \(p\) that’s nonzero wherever \(f\) is, and its variance is \[ \sigma^2 = \int \frac{f^2}{p}\,d\mathbf{x} - I^2 , \] which vanishes when \(p \propto f\) (for positive \(f\)), because then every single sample returns exactly \(I\). Of course, normalizing that perfect \(p\) requires knowing \(I\), so we never actually achieve it, but the guiding principle is clear: sample where the integrand is large, so that \(f/p\) is as close to constant as we can make it. For the singular integrand of Section 2.4.1, sampling \(r\) with a density that has the same \(r^{-\alpha}\) singularity makes \(f/p\) completely smooth. The full power of the idea shows up when \(p\) is the Boltzmann distribution and we sample it with the Metropolis algorithm, which is where the course goes next.
